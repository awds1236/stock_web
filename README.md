# stock_web — 한국 주식 수급·지표 분석

연기금 등 투자자별 수급과 기술적 지표를 **검증된 범위 안에서만** 제시하는 웹앱.

핵심 원칙: **검증 없는 신호는 화면에 올리지 않습니다.** 모든 시그널은 그 시그널의
아웃오브샘플 성과와 함께 표시됩니다.

## 지금 알아야 할 두 가지

**1. "연기금 실시간 추종"은 원천 데이터가 없습니다.**
거래소가 제공하는 연기금 *종목별* 데이터는 장 마감 후에만 나옵니다(확정 18:00
이후). 장중 HTS의 "실시간 기관 수급"은 창구분석 추정치이며 연기금 단독으로
분리되지 않습니다. 그래서 파이프라인은 `T일 확정 수급 → T+1 시가 진입`이고,
백테스트 엔진이 이 지연을 강제합니다.

**2. 이 앱은 "연기금을 따라가라"고 단정하지 않습니다.**
한국 시장 연구는 외국인 순매수의 단기 예측력은 보고하지만, 국내 기관 지분
변화에 대해서는 유의한 영향이 없다는 결과도 있습니다. 연기금·외국인·기관합계를
동일 조건에서 맞붙여 검증하는 것이 1차 산출물입니다(가설 H3).

자세한 근거는 [docs/methodology.md](docs/methodology.md).

## 현재 상태

| 단계 | 상태 |
|------|------|
| Phase 0 데이터 접근 스파이크 | 스크립트 완료, **실행에 KRX 인증키 필요** |

## 시작하기

```bash
cd backend
uv venv && uv pip install -e ".[dev]"
uv run pytest tests/ -q          # 61 passed
```

### 설정

```bash
cp backend/.env.example backend/.env
# KRX_AUTH_KEY 입력 (https://openapi.krx.co.kr 에서 발급, 일 10,000회 제한)
```

거래비용 세율은 **의도적으로 자리표시자**입니다. 한국 증권거래세율은 최근 수년간
반복적으로 바뀌었으므로, 백테스트 전에 현행 세율을 확인해 `.env`에 넣으십시오.
사용된 세율은 모든 리포트에 함께 기록됩니다.

### Phase 0 실행 (인증키 확보 후)

```bash
cd backend
uv run python scripts/probe_krx.py --all
```

이 스크립트가 답하는 질문 하나: **"KRX Open API로 종목별 연기금 순매수를 받을 수
있는가?"** 결과에 따라 단일 소스로 갈지, 수급만 KRX 정보데이터시스템으로 분리할지
결정됩니다. provider 계층이 이 분기를 흡수하므로 상위 코드는 바뀌지 않습니다.

## 구조

```
backend/
  app/
    providers/    데이터 소스 추상화 (소스 의존성은 여기에만 격리)
    indicators/   순수함수 지표. flow.py 가 핵심
    backtest/     engine.py (T+1 체결·비용·거래량 제약), stats.py (DSR·PBO)
  scripts/probe_krx.py    Phase 0 판정
  tests/                  엔진 건전성 테스트 = 프로젝트의 관문
docs/methodology.md       지표 해석 근거와 한계
```

## 엔진 건전성 테스트

`tests/test_backtest_engine.py`가 통과하지 못하면 그 위의 모든 수치는 의미가
없습니다. 검증 항목:

- 완전예지 시그널이 이론적 최대 수익을 정확히 재현하는가
- **당일 수익률을 시그널로 줘도 수익이 나지 않는가** (look-ahead 누수 탐지)
- 위 테스트가 무력하지 않은가 (대조군: 완전예지는 t>10이어야 함)
- 랜덤 시그널이 무편향인가 / 정확히 비용만큼 잃는가
- 상장폐지가 -100%로 인식되는가 (생존편향 탐지)
- 비유동 종목에서 거래량 제약이 실제로 바인딩되는가

## 면책

투자자문이 아닙니다. 백테스트 결과는 아무리 엄정하게 검증해도 실제 매매 성과와
다릅니다.
