# stock_web — 한국·미국 주식 지표 해석과 예측

지표를 해석하고 **보정된 확률로 미래를 예측**하는 웹앱. 종목 단위와 섹터 단위
모두 다룹니다. 투자자 수급(한국 연기금 / 미국 내부자)은 **보조 특성**입니다.

핵심 원칙: **검증 없는 신호는 화면에 올리지 않습니다.** 모든 예측은 그 예측의
아웃오브샘플 성과와 **보정 품질**을 함께 표시합니다.

## 예측 성능의 현실적 상한 — 먼저 읽어야 할 숫자

Gu, Kelly, Xiu (2020)가 900개 이상의 예측변수로 측정한 개별종목 **월간**
아웃오브샘플 R²:

| 모형 | 월간 OOS R² |
|---|---|
| 정규화 없는 선형 | **음수** (파국적 과적합) |
| 정규화 선형 | 약 0.26% |
| 트리·신경망 | 약 **0.33~0.40%** |
| **섹터·국가 단위** | **0.29~0.95%** ← 개별종목보다 높음 |

**월간 R² 0.4%가 최첨단입니다.** 이 앱에서 그보다 훨씬 높은 값이 나오면 축하할
일이 아니라 **누수를 의심할 신호**이며, 자동으로 경고합니다.

900개를 넣어도 상위 예측변수는 일관되게 셋입니다: **모멘텀 · 유동성 · 변동성**.
그래서 이 앱의 핵심 특성은 이 세 축입니다.

**점 예측을 하지 않습니다.** "내일 75,000원" 대신 보정된 확률과 예측 구간을
제시하고, Brier 분해로 보정 품질을 항상 함께 보여줍니다. 우연보다 약간 나은데
과신하는 모형은 통상적 베팅 규칙 하에서 장기 성장률이 음수가 되기 때문입니다.

## 데이터에 관해 알아야 할 세 가지

**1. "연기금 실시간 추종"은 원천 데이터가 없습니다.**
거래소가 제공하는 연기금 *종목별* 데이터는 장 마감 후에만 나옵니다(확정 18:00
이후). 장중 HTS의 "실시간 기관 수급"은 창구분석 추정치이며 연기금 단독으로
분리되지 않습니다. 그래서 파이프라인은 `T일 확정 수급 → T+1 시가 진입`이고,
백테스트 엔진이 이 지연을 강제합니다.

**2. 이 앱은 "연기금을 따라가라"고 단정하지 않습니다.**
한국 시장 연구는 외국인 순매수의 단기 예측력은 보고하지만, 국내 기관 지분
변화에 대해서는 유의한 영향이 없다는 결과도 있습니다. 연기금·외국인·기관합계를
동일 조건에서 맞붙여 검증하는 것이 1차 산출물입니다(가설 H3).

**3. 한국과 미국은 같은 분석이 불가능합니다 — 데이터가 다릅니다.**

| | 한국 | 미국 |
|---|---|---|
| 종목별·일별 투자자 유형별 순매수 | **있음** (거래소 의무 공시) | **없음** |
| 무료 대체물 | — | SEC Form 4 내부자 매매 |
| 성격 | 기관의 순매수 | 임원·이사 **본인**의 거래 |

한국의 개별 종목 단위 투자자 유형별 공시는 문헌이 예외적 사례로 다룰 만큼 드문
구조입니다. 미국에서 같은 데이터를 얻으려면 유료 벤더 구독이 필요합니다.
**두 시장의 시그널을 나란히 놓고 우열을 비교하지 마십시오 — 서로 다른 것을 재고
있습니다.**

자세한 근거는 [docs/methodology.md](docs/methodology.md).

## 분할 매수·매도 구간

종목 화면은 지지/저항을 **분할 계획으로 환산해** 보여줍니다. "지지 후보
68,400 (터치 4회)"만 떠 있으면 그 다음이 비어 있습니다 -- 몇 회로 나눌지, 각
회차에 얼마를 실을지, 다 채워지면 평균단가가 얼마가 되는지를 사용자가 손으로
계산해야 했습니다.

계산 규칙:

| 항목 | 규칙 |
|---|---|
| 회차 수 | 기본 3분할 (최소 3, 최대 5) |
| 매수 구간 | 현재가 **아래** 지지 후보를 가까운 순으로 |
| 매도 구간 | 현재가 **위** 저항 후보를 가까운 순으로 |
| 회차 간격 | ATR(14) 이상, 최소 현재가의 2% — 0.3% 간격의 '3분할'은 한 가격에 거는 것과 같습니다 |
| 수준 부족 시 | 없는 지지선을 지어내지 않고 ATR 등간격으로 채운 뒤 **다른 배지로 표시** |
| 비중 | 균등(1:1:1) 또는 뒤가중(1:2:3) — 화면에서 전환하며 평균단가 비교 |
| 무효화 가격 | 마지막 회차보다 한 간격 더 밖. 이 선이 깨지면 근거로 삼은 수준이 전부 뚫린 것 |

**이것은 매매 신호가 아니라 산술입니다.** 근거가 되는 지지/저항은 이 앱에서
학술 근거가 가장 약한 축이고(뚫리면 의미가 반전됩니다), 분할로 나눈다고 그
약함이 사라지지 않습니다. 분할이 실제로 바꾸는 것은 진입가의 분산이 줄어든다는
점 하나이며 기대수익을 높이지 않습니다 -- 하락이 이어지면 더 많은 금액이
물립니다. 비중 방식의 우열도 이 앱은 검증하지 않았습니다.

AI 서술 분석도 같은 숫자를 받습니다. `## 분할 대응 구간` 절에서 매수·매도를
**각각 최소 3회차**까지 회차별로(가격·거리·비중·누적 평균단가·근거) 서술하며,
변동성으로 채운 회차는 지지선이 아니라고 반드시 밝히도록 프롬프트가 요구합니다.
모델이 숫자를 지어내지 못하게, 서술의 근거는 전부 프롬프트에 실어 보냅니다.

## 유니버스: 코스피 200 · 코스닥 50

KRX 는 전 종목(2,700+)을 한 번에 줍니다. 전부 담으면 수집이 느려질 뿐 아니라,
횡단면 예측 모형이 하루 거래가 몇 백만원인 종목들의 노이즈에 지배됩니다.

**보드별로** 자릅니다. 하나의 상한으로 시총 줄을 세우면 코스닥이 사실상
사라지는데(코스피 대형주가 상위를 전부 차지합니다), 코스닥은 코스피와 가격
움직임의 성격이 다르므로 몇 종목만 섞여 들어오면 모형에는 노이즈로만 남습니다.

| 시장 | 상한 | 기준 |
|---|---|---|
| KOSPI | 200종목 | 최근 일자 시가총액 (없으면 거래대금) |
| KOSDAQ | 50종목 | 같음 |
| 미국 | 64종목 (고정 목록) | 대형주 하드코딩 — 지수 구성종목으로 교체 예정 |

유니버스는 **한 번 정해지면 유지합니다.** 한국 히스토리는 여러 번에 나눠
받으므로, 매 실행마다 상위 N을 다시 뽑으면 실행마다 종목 집합이 달라지고
종목별 시계열에 구멍이 생깁니다.

예외는 상한이 **줄었을 때**뿐입니다. 그때는 유지 규칙이 오히려 문제가 됩니다 --
수집이 저장된 목록을 따르므로, 상한만 바꿔서는 이미 쌓인 DB(CI 캐시)가 예전
크기를 영원히 유지합니다. 그래서 위반이 감지되면 한 번 다시 뽑고 빠진 종목을
저장소에서도 지우며, 무엇이 지워졌는지 수집 경고에 남깁니다.

**생존편향**: 선정 기준이 *현재* 시가총액이므로 과거 구간에 대해서는 미래
정보를 쓴 셈입니다. 지금 대형주인 종목만 남으니 표본이 '그동안 살아남아 커진
기업'에 쏠립니다. 화면의 수치를 볼 때 이 점을 감안하십시오.

## 분석은 대상 단위로, 버튼을 눌렀을 때만

이전에는 화면을 열 때마다 유니버스 전체를 다시 계산했습니다. 수백 종목을 전부
분석하면 수십 초가 걸리는데 그 대부분은 **사용자가 보지도 않을 종목의 계산**
입니다. 지금은 보고 있는 대상만 계산합니다.

| 단위 | 실행 방법 | 비용 |
|---|---|---|
| 종목 | `/stocks` 에서 종목 선택 → **분석 실행** | 즉시 (0.1초 내외) |
| 업종 | `/sectors` 표의 **분석** 버튼 | 즉시 |
| 시장 | `/market` 진입 시 자동 | 1~2초 |
| 예측(워크포워드) | 종목 분석에서 **체크박스로 선택** | 첫 실행 수십 초, 이후 재사용 |

차트와 지표는 종목을 고르면 **자동으로** 뜹니다 — 저장된 데이터를 읽는 값싼
작업을 버튼 뒤에 둘 이유가 없기 때문입니다. 버튼 뒤에 있는 것은 유니버스 전체를
훑는 상대분석과 유료인 AI 호출뿐입니다.

캐시 무효화 기준은 시간이 아니라 **데이터 지문**(마지막 일자 + 행 수)입니다.
TTL 로 두면 자동 수집이 새 데이터를 넣어도 옛 예측이 남아, 화면의 시세와 예측이
서로 다른 날짜를 가리킵니다.

## AI 서술 분석

숫자를 읽는 것과 그것이 무슨 뜻인지 쓰는 것은 다른 일입니다. 지표 화면은 상태를
서술하고, AI 는 그 서술들을 엮습니다. 다만 **엄격하게 제한된 조건**에서만입니다.

| 분석 | 대상 | 무엇을 씁니까 |
|---|---|---|
| 종목 | 선택한 종목 | 추세·모멘텀·변동성, 지켜볼 지점, 반대 해석 |
| 업종 | 선택한 업종 | 업종 현황, 내부 분화(리더 vs 부진), 반대 해석 |
| 시장 | 한국/미국 전체 | 시장 상태, 업종 지형, **주목할 종목**, 반대 해석 |

**모델은 검색하지 않고 기억에 의존하지 않습니다.** `app/reports.py` 가 계산한
숫자를 JSON 으로 넘기고 그 안에서만 서술하게 합니다. 실적·뉴스·공시·목표주가는
프롬프트에 없고, 없는 것은 "데이터에 없다"고 쓰도록 지시합니다. 점 예측과
매수/매도 추천은 시스템 프롬프트에서 금지합니다.

화면에 보이는 숫자와 AI 에게 넘기는 숫자는 **같은 dict** 입니다. 프롬프트를
따로 만들면 화면에는 RSI 62 가 찍혀 있는데 AI 는 다른 값을 근거로 서술하는
상황이 되고, 그건 사용자가 발견할 방법이 없는 종류의 오류입니다.

### 분석 기록 (`/ai-logs`)

실행한 AI 분석은 전부 DuckDB 에 저장됩니다 — 결과 문장뿐 아니라 **그때 모델에게
넘긴 숫자까지** 함께. 이유는 셋입니다:

* 호출은 유료이고 **같은 데이터로 다시 물어도 같은 문장이 나오지 않습니다.**
* 3개월 뒤 "무엇을 근거로 그렇게 썼나"를 볼 수 없다면, AI 서술은 검증 불가능한
  인상으로만 남습니다.
* 실패한 호출도 이유와 함께 남깁니다. 안 남기면 같은 실패를 반복합니다.

### 설정 (`/settings`)

`OPENAI_API_KEY` 를 설정 화면에 넣으면 AI 분석이 켜집니다. 키가 없으면 버튼이
비활성화될 뿐, 시세·지표·예측은 전부 그대로 동작합니다.

모델 이름과 엔드포인트는 같은 화면에서 바꿉니다. **앱은 모델 이름을 검증하지
않고 그대로 전달합니다** — 공급자가 모델을 추가·개명해도 코드 수정 없이 쓸 수
있어야 하고, 존재하지 않는 이름이면 공급자의 오류 문구를 그대로 보여주는 편이
정확하기 때문입니다. 앱이 임의로 다른 모델로 바꾸면 어떤 모델이 답했는지 알 수
없게 됩니다.

키만 암호화 저장되고 모델 이름은 평문으로 보관·표시됩니다. 모델 이름을
마스킹하면 분석 결과의 출처를 확인할 방법이 사라집니다.

## 화면은 두 모드로 동작합니다 — 실행 시점에 정해집니다

이 앱의 화면은 빌드 때 "정적이냐 아니냐"가 못 박히지 않습니다. **열 때마다
백엔드가 살아있는지 확인해** 모드를 정합니다.

| | 실시간 (백엔드 연결됨) | 스냅샷 (백엔드 없음) |
|---|---|---|
| 시세·지표·분석 | 지금 계산한 값 | CI 가 구운 값 |
| 현재가 | 백엔드가 조회 | **브라우저가 직접 조회** |
| 수집·설정·AI | 가능 | 불가 (이유를 화면에 표시) |
| 예측 기간 | 5/21/63일 | 21일만 |

상단 막대가 지금 어느 쪽인지 항상 표시합니다. 초록이면 실시간, 노랑이면
스냅샷입니다. **낡은 값을 지금 값처럼 보여주지 않는 것**이 이 앱에서 가장
중요한 규칙입니다 — 그 오류는 조용하고, 발견되지 않으며, 판단에 직접
영향을 줍니다.

### 배포된 사이트에 백엔드를 붙이기 (재배포 불필요)

GitHub Pages 에 올린 사이트에서 **설정 → 백엔드 연결**에 주소를 넣으면, 그
순간부터 전 화면이 살아있는 데이터를 씁니다. 다시 빌드하지도 배포하지도
않습니다. 주소는 `localStorage` 에 저장되므로 **이 브라우저에만** 남고, 같은
사이트를 여는 다른 사람에게는 영향이 없습니다.

백엔드 쪽에서 그 출처를 허용해야 합니다:

```bash
CORS_ORIGINS=https://<계정>.github.io
```

와일드카드(`*`)를 넣지 마십시오. 이 API 에는 인증정보 입력 엔드포인트가 있어,
임의의 사이트가 사용자의 브라우저를 통해 호출할 수 있게 됩니다.

### 백엔드 띄우기

```bash
docker build -t stock-web-backend ./backend
docker run -p 8000:8000 \
  -e CORS_ORIGINS=https://<계정>.github.io \
  -v stock-web-data:/data \
  stock-web-backend
```

볼륨을 반드시 두십시오. 컨테이너를 다시 만들 때마다 10년치를 다시 받으면 무료
소스가 차단으로 응답합니다. 인증정보 암호화 키도 `/data` 에 생깁니다.

`https` 사이트에서 `http` 백엔드는 브라우저가 차단합니다(혼합 콘텐츠). Pages
사이트에 붙이려면 백엔드도 https 로 노출해야 합니다.

## 현재가: 고른 종목 하나만, 1분에 한 번

가격 조회에는 세 가지 규칙이 있습니다. 셋 다 같은 이유에서 나왔습니다 --
**무료 시세 소스가 차단으로 응답하게 만드는 것은 대개 요청의 빈도입니다.**

1. **고른 종목만 조회합니다.** 목록(시장 화면의 주목 종목, 관찰 목록)은
   스냅샷 종가로 전부 보여주고, 현재가는 사용자가 고른 한 종목만 부릅니다.
   예전에는 표에 있는 12종목을 전부 조회해서, 화면을 열어두는 것만으로
   1분마다 12번의 요청이 나갔습니다.
2. **같은 종목은 60초에 한 번.** 갱신 주기 설정과 **별개로** 강제되는
   하한입니다. 화면이 몇 개든, 컴포넌트가 다시 마운트되든, 새로고침을 몇 번
   누르든 네트워크로 나가는 것은 분당 1회입니다(브라우저·백엔드 양쪽에
   각각 캐시가 있습니다). 쿨다운 중에는 새로고침 버튼이 남은 초를 표시합니다.
3. **주기 선택은 1분/5분/10분.** 15초·30초 선택지를 없앴습니다. 원천이 15분
   이상 지연된 값이라 값은 그대로면서 요청만 늘어납니다.

| 경로 | 조건 | 성격 |
|---|---|---|
| 백엔드 조회 | 백엔드 연결됨 | 서버가 대신 호출. 실패가 서버 로그에 남음 |
| 브라우저 직접 조회 | 백엔드 없음 (**미국·한국 모두**) | 무료 소스를 브라우저가 직접 호출 |
| 스냅샷 종가 | 위 둘이 실패 | **움직이지 않음** — 배지로 구분 표시 |

### 한국 종목의 당일 가격

예전에는 한국에 이 경로가 아예 없었습니다. "무료 장중 소스가 없다"고 보고
조회를 시도조차 하지 않았고, 그래서 한국 종목 화면은 배포 시점의 종가에
멈춰 있었습니다.

KRX Open API 에 장중 시세가 없다는 것과, **어떤** 무료 소스에도 없다는 것은
다른 이야기입니다. 종목코드에 상장 시장별 접미사를 붙이면 미국과 같은 소스가
한국 종목의 지연 시세를 줍니다:

```
005930 (KOSPI)  ->  005930.KS
247540 (KOSDAQ) ->  247540.KQ
```

그래서 `prices` 테이블에 `board`(KOSPI/KOSDAQ) 컬럼을 두고 수집 때 채웁니다.
KRX 응답에 원래 들어 있던 값인데, 저장 직전에 `market='KR'` 로 덮여 사라지고
있었습니다. 보드를 모르는 종목은 두 접미사를 차례로 시도하되, 그건 요청이 두
배가 되는 경로이므로 예외입니다.

한계는 미국과 같습니다 -- 비공식 경로라 예고 없이 막힐 수 있고, **지연
시세이며 체결 가격이 아닙니다.** KRX 공식 실시간이 아닙니다.

브라우저 직접 조회는 비공식 엔드포인트에 의존합니다. 차단되거나 규격이 바뀌면
조용히 실패하는 대신 이유를 화면에 적고 스냅샷 종가로 물러납니다.

**동작 여부는 환경마다 다릅니다** — 브라우저·네트워크·소스 정책에 달려 있어
한 곳에서 확인한 결과가 다른 곳에서 같다는 보장이 없습니다. 그래서 추측하게
두지 않고 `/settings` 의 **실시간 가격 진단**에서 버튼 하나로 실제 조회를 해
보고 결과를 확인할 수 있게 했습니다(미국·한국을 각각 한 번씩 부릅니다).
막혀 있으면 백엔드를 연결하는 것이 확실한 해법입니다 — 서버는 CORS 제약을
받지 않습니다.

탭이 보이지 않으면 갱신을 멈추고, 다시 보이면 즉시 한 번 당겨옵니다. 배경 탭이
종일 열려 있는 것은 흔하고, 그동안의 요청은 전부 낭비입니다.

## 화면이 스스로 갱신됩니다

열었을 때 한 번만 읽고 마는 화면은 없습니다.

| 대상 | 주기 | 왜 이 주기인가 |
|---|---|---|
| 현재가 | 1분 (고른 1종목) | 원천이 지연 시세라 더 자주 물어도 같은 값 |
| 데이터 현황 | 30초 | 수집이 도는 동안 화면이 따라가야 함 |
| 시장·섹터·관찰 목록 | 5분 | 일별 집계. 수집이 돌면 알아채는 용도 |
| 종목 차트·지표 | 5분 | 수집이 돌면 마지막 봉이 갱신됨 |
| 예측 | 10분 | 캐시가 유효하면 즉시, 새 데이터면 재계산 |
| AI 분석 기록 | 1분 | 다른 탭에서 실행한 분석도 목록에 뜨게 |
| 백엔드 헬스 | 1분 | 죽었다 살아나는 것을 화면이 알아야 함 |
| 스냅샷 배포 감지 | 1분 | 새 배포가 올라오면 새로고침을 안내 |

자동 갱신은 **읽고 있던 것을 지우지 않습니다.** 5분마다 방금 실행한 분석이
사라지면 사용자는 버튼이 고장난 줄 압니다. 탭이 숨겨져 있으면 아예 쉽니다.

마지막 항목이 정적 배포의 "멈춤"을 직접 겨냥합니다. 탭을 열어둔 채 CI 가 새
데이터를 배포하면, 화면이 그 사실을 알려주고 새로고침 버튼을 띄웁니다.

## 주가 자동 수집

`/settings` 의 **주가 자동 수집**을 켜면 백그라운드에서 주기적으로 증분 갱신을
돕니다. 마지막 저장 일자에서 며칠 겹치는 구간만 다시 받습니다 — 매 주기마다
10년치를 다시 내려받으면 요청량이 수백 배가 되고 무료 소스는 조용히 차단합니다.
겹침이 필요한 이유는 휴장·지연 정정으로 생긴 구멍을 메우기 위해서입니다.

**기본값은 꺼짐입니다.** 앱을 켜자마자 외부로 나가는 네트워크 호출은 사용자가
명시적으로 선택해야 합니다. 일별 확정 데이터를 다루므로 하루에 몇 번이면
충분하며, 주기를 짧게 둬도 같은 값만 돌아옵니다.

이것은 **저장 데이터**의 갱신입니다. 화면의 현재가 갱신(1분)과는 다른
층위이며, 위의 &ldquo;현재가는 1분마다&rdquo; 절을 함께 보십시오.

### 예측 엔진 (`app/predict/`)

| 모듈 | 역할 |
|---|---|
| `features.py` | 핵심 3축(모멘텀·유동성·변동성) + 보조. 라벨은 T+1 진입 기준 |
| `model.py` | 워크포워드 재학습. **정규화 없는 모형은 제공하지 않음**. 엠바고 강제 |
| `calibration.py` | Brier 분해, 신뢰도 곡선, ECE, OOS R² + **누수 경고** |
| `sectors.py` | 섹터 집계·breadth·상대강도. 종목과 **동일한 지표 코드** 재사용 |

### 미국 데이터의 알려진 한계

무료 소스(yfinance)는 **상장폐지 종목을 제공하지 않습니다.** 엔진은 상폐를
-100%로 인식하도록 만들어져 있지만 데이터에 없으면 인식할 대상이 없습니다.
→ **미국 백테스트 성과는 생존편향으로 과대평가됩니다.** 한국(KRX)에는 이 문제가
없습니다. 완화 방법은 [methodology 4-A절](docs/methodology.md) 참조.

## 실행 방법

터미널 두 개가 필요합니다.

```bash
# 터미널 1 — 백엔드
cd backend
uv venv && uv pip install -e ".[dev]"
uv run uvicorn app.main:app --port 8000

# 터미널 2 — 프론트엔드
cd frontend
npm install
npm run dev        # http://localhost:3000
```

브라우저에서 `http://localhost:3000` 을 엽니다.

### 미국 주식은 인증키 없이 바로 시작합니다

개요 화면의 **&ldquo;미국 데이터 수집&rdquo;** 버튼을 누르면 yfinance 로 10년치를
받아옵니다. 키 발급 없이 종목 분석·섹터 분석·예측을 모두 쓸 수 있습니다.
한국 주식만 KRX 인증키가 필요하며, 설정 화면에서 입력합니다.

### 화면

| 경로 | 내용 |
|---|---|
| `/` | 데이터 현황, 수집 실행 |
| `/market` | 시장 상태·내부지표·업종 지형 + **규칙에 걸린 주목 종목** + AI 분석 |
| `/watchlist` | 자동 스크리닝 관찰 목록 |
| `/stocks` | 차트·지표(자동) + **종목 단위 분석**(버튼) + AI 분석 |
| `/sectors` | 섹터 수익률·상대강도·breadth + **업종 단위 분석**(버튼) + AI 분석 |
| `/forecast` | 보정된 확률 + **신뢰도 곡선과 skill score** |
| `/ai-logs` | AI 분석 이력 — 결과 문장과 **그때 넘긴 숫자**를 함께 보관 |
| `/settings` | 인증정보(암호화) · AI 모델 · 주가 자동 수집 |
| `/methodology` | 예측 성능의 현실적 상한과 근거 논문 |

예측 화면은 모형이 쓸모없으면 **쓸모없다고 크게 표시합니다.** skill score 가 0
이하이면 &ldquo;이 예측을 매매 근거로 삼지 마십시오&rdquo; 배너가 뜹니다.

### 알려진 제약

- **DuckDB 는 쓰기 프로세스를 하나만 허용합니다.** API 서버와 수집 스크립트를
  동시에 돌리면 503 과 함께 안내 메시지가 나옵니다.
- 종목 수가 적으면 아웃오브샘플 R² 추정치의 분산이 매우 큽니다. 신호 없는
  데이터에서 12종목은 R² +0.028, 40종목은 -0.002 가 나왔습니다.
  **수십 종목 미만 유니버스의 R² 는 신뢰하지 마십시오.**

## GitHub Pages 호스팅

GitHub Pages 는 **정적 파일만** 서빙하므로 백엔드가 거기서 돌 수 없습니다.
대신 `.github/workflows/pages.yml` 이 이렇게 동작합니다:

```
GitHub Actions (미국 장중 2시간마다 + 양 시장 마감 후 + push + 수동)
  → CI 러너에서 데이터 수집·예측 계산 (미국은 키 불필요)
  → API 응답을 JSON 스냅샷으로 고정 (scripts/export_static.py)
  → Next.js 정적 빌드 (output: 'export')
  → https://<계정>.github.io/stock_web/ 에 배포
```

### 활성화 방법

1. 이 브랜치를 푸시하면 워크플로가 실행되고 Pages 가 자동 활성화됩니다.
   안 되면: 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 설정.
2. Actions 탭에서 "Deploy GitHub Pages" 실행 확인 → 완료되면
   `https://<계정>.github.io/stock_web/` 접속.

### 한국은 히스토리가 자라는 데 시간이 걸립니다

미국(yfinance)은 10년치를 한 번에 주지만, **KRX Open API 는 하루치씩만**
줍니다. 10년치는 약 5,000회 요청이라 한 번의 배포로는 받을 수 없습니다.

그래서 수집은 이렇게 동작합니다:

  * 이미 저장한 날은 다시 받지 않습니다 (과거 확정 시세는 불변)
  * 일자별 요청을 병렬로 보냅니다
  * 한 번에 최대 1,100거래일까지만 받고, 나머지는 다음 실행이 이어받습니다
  * CI 는 DuckDB 파일을 실행 간에 캐시해 히스토리를 누적합니다

1,100거래일이라는 값은 실측으로 정했습니다 -- 그 아래로는 예측이 아예 나오지
않습니다:

| 거래일 | 예측 |
|---|---|
| 800 | 불가 (구간을 만들 수 없음) |
| 900 | 폴드 1 |
| 1,100 | 폴드 3 |

학습 504 + 검증 126 + 예측구간 21 만으로 부족한 이유는 **특성 워밍업**입니다.
12-1 모멘텀이 약 252거래일을 먹고 시작합니다.

히스토리가 부족한 동안에는 개요 화면이 **무엇이 왜 비어 있는지** 표시합니다.
빈 화면만 보여주면 사용자는 앱이 고장난 줄 압니다.

### 한국 데이터 포함 (선택)

키를 저장소 파일에 넣지 않고 **repo secret** 으로 주입합니다:
**Settings → Secrets and variables → Actions → New repository secret** 에
`KRX_AUTH_KEY` 추가 → 다음 배포부터 한국 데이터가 포함됩니다.
secret 이 없으면 미국만 배포됩니다.

### 정적 배포의 한계 (의도된 것)

| | 로컬 실행 | GitHub Pages (백엔드 없음) | Pages + 백엔드 연결 |
|---|---|---|---|
| 데이터 갱신 | 버튼 + 자동 수집 | Actions 스케줄 | 버튼 + 자동 수집 |
| 종목·업종·시장 분석 | 즉시 | 스냅샷 (CI 가 같은 API 를 덤프) | 즉시 |
| 예측 기간 | 5/21/63일 | 21일만 (CI 시간 절약) | 5/21/63일 |
| **현재가** | 1분마다 | **1분마다** (브라우저 직접 조회) | 1분마다 |
| AI 서술 분석 | 가능 | **불가** | 가능 |
| 설정(인증키 입력) | 가능 | 불가 — secret 으로 대체 | 가능 |
| 저장소 공개 시 | — | **사이트도 공개됨** | 사이트만 공개, 백엔드는 별개 |

AI 분석을 백엔드 없이 지원하지 않는 이유는 기술적 한계가 아니라 보안입니다.
브라우저에서 직접 호출하려면 API 키가 자바스크립트 번들에 들어가야 하고, 무료
플랜의 Pages 는 저장소가 private 이어도 항상 공개됩니다 — 즉 키를 공개하는
것과 같습니다.

**현재가는 백엔드 없이도 갱신됩니다.** 시세 조회에는 키가 필요 없으므로
브라우저가 직접 무료 소스를 호출합니다. 분석 수치만 스냅샷입니다.

주의: 무료 플랜에서 Pages 사이트는 저장소가 private 이어도 **항상 공개**입니다.
스냅샷에는 시세·지표·예측만 담기며 인증키는 어디에도 포함되지 않습니다.

| 변수 | 발급처 | 비고 |
|---|---|---|

있으며, 환경변수가 설정 화면 값보다 우선합니다.

### 비밀정보 관리

키는 **저장소에 들어가지 않습니다.** 세 겹으로 막습니다:

1. `.gitignore` — `.env` 는 추적되지 않음
2. `.githooks/pre-commit` — 스테이징된 내용에서 값이 채워진 비밀 변수를 차단.
   `.gitignore` 만으로는 `git add -f` 나 코드에 하드코딩한 키를 막지 못합니다
3. `tests/test_no_secrets_committed.py` — 추적 중인 파일 전체를 검사. 훅을 안
   깔았거나 `--no-verify` 로 우회한 경우에도 CI 에서 걸립니다

**배포 시에는 `.env` 파일을 올리지 말고 호스팅 플랫폼의 환경변수로 주입하십시오.**
`app/config.py` 는 환경변수를 우선하므로 코드 변경이 필요 없습니다.

키가 이미 유출됐다면 히스토리에서 지우는 것으로는 부족합니다 — **폐기하고
재발급**하는 것이 유일하게 확실한 대응입니다.

거래비용 세율은 **의도적으로 자리표시자**입니다. 한국 증권거래세율은 최근 수년간
반복적으로 바뀌었으므로, 백테스트 전에 현행 세율을 확인해 `.env`에 넣으십시오.
사용된 세율은 모든 리포트에 함께 기록됩니다.

## 구조

```
backend/
  app/
    providers/    데이터 소스 추상화 (소스 의존성은 여기에만 격리)
    indicators/   순수함수 지표. flow.py 가 핵심
    predict/      특성·워크포워드·보정·섹터
    backtest/     engine.py (T+1 체결·비용·거래량 제약), stats.py (DSR·PBO)
    ai/           AI 서술 분석: client(HTTP) · prompts(제약) · logs(이력)
    reports.py    **숫자를 만드는 유일한 자리.** 화면과 AI 가 같은 dict 를 씁니다
    refresh.py    주가 자동 수집 루프 (증분·기본 꺼짐·실패해도 안 죽음)
    prefs.py      비밀이 아닌 설정 (모델 이름·갱신 주기)
    credentials.py 비밀 설정 (암호화·마스킹)
  scripts/probe_krx.py    Phase 0 판정
  tests/                  엔진 건전성 테스트 = 프로젝트의 관문
docs/methodology.md       지표 해석 근거와 한계
```

`reports.py` 와 `ai/` 가 분리된 이유: 계산과 서술은 다른 일이고, 서술이 계산을
건드리면 안 됩니다. AI 는 `reports.py` 의 출력을 읽기만 하며 숫자를 만들지
않습니다.

`prefs.py` 와 `credentials.py` 가 분리된 이유: 인증정보는 암호화하고 조회 시
마스킹해야 하지만, 모델 이름은 **보여야** 합니다. 같은 취급을 하면 어떤 모델이
답했는지 확인할 방법이 사라지고, 반대로 API 키를 prefs 에 두면 평문 JSON 으로
디스크에 남습니다. 요구가 정반대이므로 저장소를 나눴습니다.
